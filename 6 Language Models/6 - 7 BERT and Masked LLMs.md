# BERT and Masked Language Models

The language models we have seen have been engineered for next token prediction. This is not the only learning task we can train a language model for.

Each learning task comes with its own bias; to be good at different things (they literally learn differently).

Next token prediction LLMs are good at:

- question answering
- summarisation

But are not so good at tasks where knowing future tokens are useful:

- named entity recognition
- part of speech tagging
- translation

## Bidirectional Encoders and Masked Language Models

Use attention to map a sequence of input embeddings to a sequence of output embeddings of the same length such that output embeddings have been *contextualised* with information from the *entire* input sentence.

To accomplish this a **different learning task must be applied**.

This learning task categorises *masked language models*.

Idea: Corrupt the input text and ask the model to recover the original text

- bidirectional self attention layers are used
- input sentence first has to be tokenised (BPE)
- processing takes palce on subwork tokens

## BERT - Bidirectional Encoder Representations from Transformers

Idea: replace some fraction of words in the input with $[MASK]$ token to be predicted.

$$h1,...,h_t = encoder(w1,...,w_t)$$
$$y_i ~ Aw_i + b$$

- Loss is only added for masked words.
- We are learning $p_\theta (x|x')$

BERT masking strategy:

- predicts a random 15% of subwrord tokens
	- replaced the input word with $[MASK]$ 80% of the time
	- replace input word with random token 10% of the time
	- leave the input word unchanged 10% of time (but still predict)
		- bias the representation to actual words
- it has been shown that the Masking Strategy is not so determinant.

### NSP - Next Sentence Prediction - Sentence embeddings with BERT

*Next sentence prediction (NSP)*

Bert is also trained on a second learning tasks to understand the relationships between sentences

This is important for many downstream tasks:

1. paraphrase detection
2. semantic textual similarity
3. sentence entailment

	- do the sentence entail or contradict eachother?

4. answer sentence selection

	- is the answer contained in the following sentence?

#### NSP - Next Sentence Prediction
NSP is a binary decision task is trivially generated by any monolingual corpus.

**Requirments**

- $[CLS]$ token prepended to the first sentence.
	- this can be used as the sentence embedding.
-  $[SEP]$ token placed between the two sentences
- segment token embeddings - encode for each token which sentence it belongs to.

**Task**

- predict whether one sentence follows the other or is randomly sampled.
**Training data**

	- an actual pair of adjacent sentences from the corupus (50%)
	- randomly selected pair  50%

## BERT Details

Two models were released:

- BERT-base: 12 layers, 768-dim hidden states, 12 attention heads, 110 million params.
- BERT-large: 24 layers, 1024-dim hidden states, 16 attention heads, 340 million params.

Trained on:

	- BooksCorpus (800 million words)
	- English Wikipedia (2,500 million words)
- Pretraining is expensive and impractical on a single GPU.
	- BERT was pretrained with 64 TPU chips for a total of 4 days.
- Finetuning is practical and common on a single GPU
	- “Pretrain once, finetune many times.”

BERT was massively popular and hugely versatile; finetuning BERT led to new state-of- the-art results on a broad range of tasks:

- QQP: Quora Question Pairs (detect paraphrase)
- QNLI (natural language inference
- SST-2 (sentiment analysis)
- CoLA (corpus of linguistic acceptability)
- STS-B (semantic textual similarity)
- MRPC (Microsoft paraphrase corpus)
- RTE (natural language inference)

### RoBERTa - Robustly Optimised BERT Approach

- longer training over more data.
- no more NSP task (to simplify the model training which lead to better results.)
- The key improvement was to dynamically change the masking pattern.
- XML-RoBERTa
	- training on data from multiple languages
	- Examples from low resource languages need to be sampled more frequently
	- Low resource languages tend to be ”influenced” by high resource ones
	- Empirically it has been observed that over a certain threshold on the number of languages the overall performance degrades

## Contextual Embeddings

Unlike Static word embeddings (word2vec..) that representing the meaning of word types (independent vocabulary entries), contextual embeddings represent *word instances* and are more useful for certain tasks i.e measuring the semantic similarly of two words in context (in sentences).

We can extract contextual embeddings from masked language models. But is it not clear which layer is the best to extract from.

- commonly the last 4 layers are used (for transformers).

### Instance semantics

**How to establish in context(instance) semantics?**

1. compute embeddings of a set of words from a controlled dataset.
2. compute distance fromour word instance emedding and our templated words.

**What is the right similarity function to use?**

With cosine similarity, it has been shown that any two embeddings from BERT have a similarity close to 1

- all pairs of BERT embeddings are **anisotropic** (they point in the same direction)

Timkey proposes a standardisation to make the vectors more isotropic:

$$\mu = \frac{1}{|C|}\sum_{x \in C}x$$
$$\sigma = \sqrt{\frac{1}{|C|}\sum_{x \in C}(x-\mu)^2}$$
$$z = \frac{x-\mu}{\sigma}$$

Timkey, W. and M. van Schijndel, “All bark and no bite: Rogue dimensions in transformer language models obscure representational quality. EMNLP 2021.

## Fine Tuning BERT

### LORA

Fine-tuning by pre-training is expensive, instead, we can exploit the parallelisation over tokens of attention matrix multiplication.

Say we need to update a matrix $W: n \times m$

- $W$ can be approximated by $AB$ (Low Rank Approximation) of size $A: N \times r$ and $B: r \times d$
- We apply gradient descent to A and B and then we update $W=W+AB$

## Named Entity Recognition with MLLMs

See: [[Sequence Labelling#Named Entity Recognition (NER) |Named Entity Recognition]]

NER is a token level sequence labelling task:

- Find a space of text that constitutes proper names and tag the type of the entity.

- example tags: PERSON, LOCATION,  ORGANISATION, GEO-POLITICAL-ENTITY

**Idea:** use BIO tagging to classify tokens -> Begin, Inside, outside tokens for each token.

- "Citing high fuel prices, ORG(B - ORG) United(I) Airlines(I) said(O) Friday(B - time) it(O)..."

**Simple approach:**

- Add a classifier on top of each input token whose output is either B,I,O and then compare it with the expected BIO tag.
- Extra care needs to be taken to ensure the correspondence of the BIO token to the output of the tokeniser of the LLM
